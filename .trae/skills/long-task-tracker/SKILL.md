# 超长任务追踪器

本skill为超长、复杂任务提供结构化管理方案，确保稳定执行与进度可追溯性。

## 核心原则

1. **稳定优先** - 不追求速度，优先确保稳定执行和进度可追溯
2. **原子任务拆分** - 避免一次阅读多个文件或执行多条任务，每个任务条目应原子化、聚焦
3. **进度追踪** - 每完成一条任务后立即更新追踪文档
4. **自提醒机制** - 将所有重要注意事项写入追踪文档，确保每次阅读都能提醒自己遵循重点

## 调用时机

- 启动复杂多步骤任务（10+子任务）
- 跨多个会话的任务
- 需要精细进度追踪的任务
- 用户提及"超长任务"、"复杂任务"或需要进度文档时

## 追踪文档结构

创建一个markdown文件（如 `TASK_TRACKER.md`），包含以下章节：

```markdown
# 任务: [任务名称]

## 状态概览
- **启动时间**: [时间戳]
- **最后更新**: [时间戳]
- **当前阶段**: [阶段名称]

## 重要注意事项 (每次必读)
- [关键提醒 1]
- [关键提醒 2]
- [需遵循的约束或模式]

## 任务列表

### 阶段 1: [阶段名称]
| 编号 | 任务 | 状态 | 开始时间 | 完成时间 | 备注 |
|---|------|--------|---------|-----------|-------|
| 1.1 | [任务描述] | [>] | [时间] | [时间] | [可选] |
| 1.2 | [任务描述] | [ ] | - | - | [依赖 1.1(若有依赖关系)] |

### 阶段 2: [阶段名称]
...

## 会话日志
| 时间 | 操作 | 结果 |
|------|--------|--------|
| [时间戳] | [做了什么] | [结果] |

## 断点恢复
- **最后完成任务**: [编号]
- **下一步操作**: [接下来做什么]
- **所需上下文**: [继续前需查看的文件/代码]
```

## 超长文档索引策略

当任务依赖超长文档（如1000+行的JSON文档）时，使用**行号索引**避免上下文溢出：

### 索引结构示例

```markdown
## 原始文档位置
- CDDA文档: `h:\CDDA\...\doc`
- **ITEM.md**: `h:\CDDA\...\doc\JSON\ITEM.md` (约1525行)
- JSON_INFO.md: 包含Item字段的详细说明

## 原始文档结构索引 (ITEM.md)

| 章节 | 行号范围 | 主要内容 |
|------|----------|----------|
| Generic Items | 68-180 | 通用物品字段 |
| Ammo | 182-217 | 弹药定义 |
| Armor | 293-476 | 护甲定义 |
| Books | 492-599 | 书籍定义 |
| ... | ... | ... |

## 读取策略
- **分段读取**: 每次读取200-300行
- **按需定位**: 根据行号索引使用offset/limit参数读取
- **避免全量读取**: 防止上下文溢出
```

### 索引创建方法

1. **首次扫描**: 使用Grep或搜索工具定位关键章节标题
2. **记录行号**: 将各章节的起始/结束行号记录到索引表
3. **后续使用**: 根据任务需要，按行号范围精确读取

### 分段读取示例

```
读取Ammo章节(182-217行):
Read(file_path="...", offset=182, limit=36)
```

## 执行工作流

1. **初始化**: 创建追踪文档，完整拆分任务
2. **每个任务前**:
   - 阅读追踪文档
   - 查看"重要注意事项"章节
   - 检查依赖关系
   - 若需读取超长文档，查阅行号索引
3. **执行任务**: 只专注于一个原子任务
4. **每个任务后**:
   - 更新追踪文档中的状态
   - 更新时间戳
   - 更新断点恢复信息
   - 记录到会话日志
5. **会话结束**: 确保断点恢复信息清晰，便于下次继续

## 状态指示器

使用纯文本字符，便于用户直接编辑：

| 标识 | 状态 | 说明 |
|------|------|------|
| `[ ]` | 待处理 | 等待开始 |
| `[>]` | 进行中 | 正在处理 |
| `[x]` | 已完成 | 成功完成 |
| `[!]` | 失败 | 需重试或换方案 |
| `[#]` | 阻塞 | 等待依赖 |
| `[-]` | 跳过 | 不执行此任务（如超长上下文无法执行等） |

## 最佳实践

1. **一次一个任务**: 绝不批量处理多个任务
2. **即时更新**: 完成后立即更新文档，不要延后
3. **具体明确**: 任务描述应可执行、可验证
4. **记录阻塞**: 如遇阻碍，记录原因并转向下一个可用任务
5. **保留上下文**: 在备注中包含足够细节，便于中断后恢复
6. **时间追踪**: 记录时间戳以了解进度节奏、预估剩余工作量
7. **合理跳过**: 遇到无法执行或是用户要求跳过的任务（如超长上下文文档依赖），标记为 `[-]` 并在备注说明原因
8. **行号索引**: 依赖超长文档时，创建行号索引表，分段读取避免上下文溢出
